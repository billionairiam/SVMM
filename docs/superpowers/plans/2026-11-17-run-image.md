# Unified run --image implementation plan

> Execute inline using superpowers:executing-plans. User explicitly selected the single-command interface after reviewing the existing image-to-rootfs flow.

**Goal:** `svmm run --image REF` prepares and runs an OCI application, returning its status.
**Architecture:** Native CLI validates options, then execs a repository-relative Python coordinator. The coordinator reuses build-workload.py and starts the existing native workload path with a unique temporary disk.
**Scope:** Preserve low-level run/snapshot APIs and user's unrelated changes; keep Docker-based pulling and existing network/jail options. No new container runtime or network provisioning.

## Decisions
- Kernel priority: --kernel, SVMM_KERNEL, repository images/bzImage, then readable /boot kernels whose adjacent config confirms required built-in guest drivers. Invalid explicit settings fail before pulling.
- Initrd priority: --initrd, SVMM_INITRD, repository workload initramfs; build the default runtime if missing.
- Forward existing VM options; support --entrypoint, --env, --workdir, --user, --size-mb, and -- COMMAND ARGS.
- --image conflicts with --disk/--snapshot/--restore. Fresh writable disk per invocation; delete after VM exits, including signal/error paths.
- Parent coordinates prep/VM signals, forwards SIGUSR2 for snapshots, remains outside the VMM jail, and preserves child exit status.
- Assets are found relative to bin/svmm, independent of cwd. No runtime shell interpolation.

## Failure modes / tests first
- CLI accepts image but never boots or loses entrypoint/env/USER/argv.
- Missing local tag never pulls; verify real Docker pull from an isolated local HTTP registry fixture.
- Wrong cwd breaks helper/assets; defaults require user to specify a disk or initrd.
- Temp rootfs leaks on app failure/host stop; parent swallows application exit status.
- Parent fails to forward jail flags or warm-save signal.
- Conflicting flags boot or overwrite user data; invalid explicit kernel starts unnecessary pull.
